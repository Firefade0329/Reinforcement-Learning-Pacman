# 研究日志与协作规则

> 本文件放在仓库 `docs/RESEARCH_LOG.md`。任何接手的人或 AI 助手,先读这一页。

## 1. 角色与权限

| 角色 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 所有者 | 仓库所有者 | 最终决定;公开/可见性、合并发布、历史改写、标签 | — |
| 写入者 | 云端 Claude | **唯一**向 `main` 推送的角色;改代码、文档、报告 | 强制推送;未经所有者同意改写历史 |
| 本地执行者 | 本地 Claude Code | 在本机 GPU 上跑实验;结果推到 `local/...` 分支,由写入者核实后并入 | 直接推送 `main`;改动已提交的实验数据 |
| 研究讨论 | GPT(网页) | 设计实验、解释结果、审阅方案 | 写仓库 |
| 审计员 | GPT(网页,只读)、DSH(本地,只读克隆) | 独立复核代码、数据、结论 | 推送;修改被审计仓库;沿用上一轮的克隆 |

## 2. 规则

1. 同一时间只有一个角色向 `main` 写入。
2. 未经所有者同意,不改写 git 历史,不强制推送。
3. **预先注册**:每轮实验开始前,把假设、指标、训练种子、使用的测试集写进 `docs/` 并提交。看到数据后得到的解释,标注为"探索性"。
4. **保留测试集**:当前公开的测试种子(10000–10299)已被看过很多次,只用于复现旧结论。新的结论必须用从未参与任何决策的新种子或新地图,并且一次性使用。预注册研究的封存测试种子见 `docs/prereg/README.md`;代码层面只有 `scripts/prereg.py final-eval`(完整性清单加显式 `--unseal`)能读取它们。
5. 每轮记录:代码版本(commit)、配置、结果目录、中断、失败。保留失败结果和被否定的结论。
6. 每个阶段结束请审计员从全新克隆独立复核,再进入下一阶段。
7. 隐私(**新增公开内容规则**):今后新增到公开仓库的内容不放本机路径、个人信息、给 AI 助手的操作指令文件、审计员报告原文。**已接受的遗留**(所有者决定不动):已提交的旧日志里的容器路径;历史中已删除的内部提示词文件;早期报告里的系统信息行(`results_gpu/LOCAL_RUN_REPORT.md` 的设备型号表)。

## 4. 已知局限(随阶段更新)

- 每格仅 3 个训练种子,置信区间不含训练种子方差。
- 单张地图;`hard` 场景只改幽灵追击概率,不改地图。
- 两套实验(12 万步 CPU、30 万步 GPU)是同一代码和超参下的两次运行,不构成独立实现的复现。
- GPU 上的评估结果换设备复算会有差异(约 0–30% 的测试局逐局结果不同),跨设备比较需固定评估设备。

## 5. 技术记录

- **验证去重对所有训练路径生效**:当训练预算恰好落在评估边界上时,不再对同一权重重复做"最终验证"(30 万步、每 2 万步评估时为 15 次,而不是 16 次)。已提交的旧运行(`results/`、`results_gpu/`)早于这一改动,不受影响,其日志里仍有重复的最后一行。**以后若用新代码重跑旧配置,验证行会比旧日志少一次**;best 的选择不变(有测试:权重相同、严格大于才更新)。
- **Windows 上的峰值内存**(`pacman_rl/provenance.py` 的 ctypes 实现,提交 `c4bd147`)已在真实 Windows 上确认:`peak_memory()` 返回正数、`peak_memory_error` 为空(工作集约 508.9 MB、提交约 1500 MB),Windows 上的完整测试全部通过。此前 `9e46da1` 在 Windows 上因 64 位伪句柄溢出返回 `None`,云端无法复现,靠本地执行者发现。
- **smoke 的两个 profile(quick、load)相互独立**:运行名、报告文件和续训检查目录都带 profile 名(见 `docs/prereg/README.md`);此前它们共用运行名,`load` 会跳过 `quick` 留下的同名运行并覆盖其报告。
