# 研究日志与协作规则

> 本文件放在仓库 `docs/RESEARCH_LOG.md`。任何接手的人或 AI 助手,先读这一页。

## 1. 角色与权限

| 角色 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 所有者 | 仓库所有者 | 最终决定;公开/可见性、合并发布、历史改写、标签 | — |
| 写入者 | 云端 Claude | **唯一**向 `main` 推送的角色;改代码、文档、报告 | 强制推送;未经所有者同意改写历史 |
| 本地执行者 | 本地 Claude Code | 在本机 GPU 上跑实验;结果推到 `local/...` 分支,由写入者核实后并入 | 直接推送 `main`;改动已提交的实验数据 |
| 研究讨论 | GPT(网页) | 设计实验、解释结果、审阅方案 | 写仓库 |
| 审计员 | GPT(网页,只读)、DSH(本地,只读克隆) | 独立复核代码、数据、结论 | 推送;修改被审计仓库;沿用上一轮的克隆 |

## 2. 规则

1. 同一时间只有一个角色向 `main` 写入。
2. 不改写 git 历史,不强制推送。
3. **预先注册**:每轮实验开始前,把假设、指标、训练种子、使用的测试集写进 `docs/` 并提交。看到数据后得到的解释,标注为"探索性"。
4. **保留测试集**:当前公开的测试种子(10000–10299)已被看过很多次,只用于复现旧结论。新的结论必须用从未参与任何决策的新种子或新地图,并且一次性使用。
5. 每轮记录:代码版本(commit)、配置、结果目录、中断、失败。保留失败结果和被否定的结论。
6. 每个阶段结束请审计员从全新克隆独立复核,再进入下一阶段。
7. 隐私:公开仓库里不放本机路径、个人信息、给 AI 助手的操作指令文件、审计员报告原文。

## 4. 已知局限(随阶段更新)

- 每格仅 3 个训练种子,置信区间不含训练种子方差。
- 单张地图;`hard` 场景只改幽灵追击概率,不改地图。
- 两套实验(12 万步 CPU、30 万步 GPU)是同一代码和超参下的两次运行,不构成独立实现的复现。
- GPU 上的评估结果换设备复算会有差异(约 0–30% 的测试局逐局结果不同),跨设备比较需固定评估设备。
