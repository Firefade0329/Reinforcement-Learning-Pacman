## 3. Configuration

- Steps: 300000 environment steps per run; `eval_every` = 20000; device: `cuda` for the convolutional networks, CPU for the MLP.
- Parallelism: **planned 3, actual 2** (see section 7); in the late ablation phase it was adjusted further according to memory, with at most 2 convolutional training processes at the same time.
- Total time: about 12 hours 40 minutes (including two interruptions and restarts).
- 39 runs in total: baselines + tabular ×3, the depth matrix (mlp / cnn2 / res2 / res4 / res8, 3 seeds each), 9 MLP ablations, 9 ResNet-4 ablations, 3 ResNet-4 raw-grid controls.

**All 39 runs completed**, each has a `test_standard.json`, there is no `FAILED`, no stderr output, and no leftover `.lock`.

1 MUST item failed (M1). **The true situation of M1 has two layers:**
1. When the acceptance script itself called pytest it replaced the environment variables with a dictionary containing only `PYTHONPATH` and a Linux-style `PATH`; on Windows variables such as `SystemRoot` were missing, the import failed, and it reported "1 error"; this is the script being incompatible with Windows, not a test result.
2. Running `python -m pytest tests -q` directly (output in `pytest_output.txt`): **45 passed, 1 failed**, the failure being `test_stale_lock_is_taken_over`. Cause: `run_experiments.py` uses `/proc/<pid>` to decide whether the process holding the lock is alive; Windows has no `/proc`, so it conservatively assumes "still alive" and does not automatically take over a stale lock. Training itself is not affected; a leftover `.lock` has to be deleted by hand. I did not change the test or this piece of code.

`acceptance.sh --quick` (M2) was not run.

## 7. Problems encountered and how they were handled

1. **Test failures (Windows compatibility)**: the first pytest run gave 44 passed, 2 failed.
   - `test_training_resumes_after_interruption`: at resumption `np.load` opened `resume_replay.npz` and never closed it; Windows does not allow overwriting an open file, so the next checkpoint save raises `PermissionError`. **Fixed**: changed to `with np.load(...) as data:`, 3 lines in all, committed separately (`dqn.py`); after the fix this item passes. **Note: the `dqn.py` in the new cloud history does not have this fix (`np.load` is still not closed); this branch contains only the results directory, not this patch**.
   - `test_stale_lock_is_taken_over`: not fixed, see section 6.
2. **Memory pressure**: the machine has 15.7 GB, and resident processes such as the Claude desktop application take about 3.6 GB. The parallelism was reduced from 3 to 2; in the ablation phase I tried running `algo` and `algo_mlp` in parallel, and when the combination of three training processes running at the same time occurred, the available memory dropped to about 0.7 GB and the system commit headroom to about 1 GB, so I stopped `algo`, reduced to 1 parallel process and resumed; after `algo_mlp` finished I started the second `algo` process again. No run was killed after that.
3. **The main script was split up**: to let the ablations run in parallel, I terminated only the bash shell of the main script (the python process of `algo_mlp` kept running), and the `algo` phase was started as a separate `run_experiments.py algo` process (the two processes divide the work via the run locks). Therefore `make_report.py` and `check_acceptance.py` were not run automatically by the main script, but manually after all training had finished.
4. **Leftover `.lock`**: on Windows they are not taken over automatically; after each interruption I confirmed that no python process was left and that the pid of the lock holder no longer existed, and only then deleted the 5 `.lock` files by hand (mlp_s0 / s1 / s2, res4-nodouble_s0 / s1).
5. **`make_report.py` reports an encoding error on Windows**: the default cp1252 cannot write Chinese. Without changing the code, setting the environment variable `PYTHONUTF8=1` made it work.
6. **`.gitignore` covers only `results/runs/...`, not `results_gpu/`**: at the end of training `resume.pt` and `resume_replay.npz` were removed automatically (they are not in the final directory), so there are no large files; during training they were excluded with the repository-local `.git/info/exclude`.
7. **Details of `RESULTS.md`**: the figure links point to `../results/figures/...` (the default of the generating script), while the actual figures are in `figures/` of this directory; section 7 "acceptance-threshold verdicts" is empty. This auto-generated report was not edited by hand; for the acceptance output see `check_acceptance_output.txt`.
8. **Log merging**: `longrun_attempt1.log` and `longrun_algo_attempt1.log` are the first logs from before the interruption; `longrun.log`, `longrun_algo.log` and `longrun_algo2.log` are the later logs.
