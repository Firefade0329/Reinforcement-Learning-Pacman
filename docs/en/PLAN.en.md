# Pacman reinforcement-learning upgrade plan and acceptance procedure

> Status: v1 (finalised before implementation). The acceptance thresholds were fixed when this file was committed; if they need to be adjusted during implementation, this must be written into the "deviation record" in section 9 and must not be changed silently.

## 1. Goals

Upgrade the 2023 Java Pacman (4-state tabular Q-Learning + hand-written dodging rules) into:

1. **A reproducible Python experiment platform**: a faithful port of the original game rules, with a unified evaluation protocol.
2. **A deeper neural-network agent**: from MLP → CNN → residual CNN, combined with Double / Dueling / n-step DQN, **using ablation experiments to show whether "depth" and "algorithmic improvements" are each useful**, rather than assuming by default that "deeper is better".
3. **Verifiable**: every step has commands, quantitative thresholds and automatic check scripts.

The original Java code is **kept in place, untouched** (it depends on the relative paths `Images/` and `data/`); all new code goes under `python/` and `docs/`.

## 2. Diagnosis of the current state (verified facts)

| Item | Fact | Consequence for the plan |
|---|---|---|
| Map | 32×24, 378 walkable cells, **one pellet per cell** (except the spawn cell, at most 377 can be eaten), no dead ends, fully connected | Fixed map; all-pairs shortest paths can be precomputed |
| Ghosts | 3; `nextInt(10) > 2` ⇒ **70% random walk, only 30% chase**; no turning back | Weaker than the README suggests; a separate "strong chase" scenario is needed to test generalisation |
| Termination | Collision on the same cell loses (checked once after Pacman moves and once after the ghosts move); eating everything wins; truncation at 1000 steps | Environment copied as is |
| State | Only "BFS direction of the nearest pellet" (4 states); the 64-state version in the comments of `QLearning.java` is **not implemented** | Complete the tabular baseline with 64 states |
| Dodging | **Entirely hand-written rules** (if a ghost is within 5 cells, a fixed escape), and the Q update is skipped while escaping; there is also a bug: `closestGhost` takes the **last** nearby ghost in the loop rather than the nearest | The old policy = "BFS pellet eating + hand-written escape", replicated exactly (including this quirk) as the `legacy` baseline |
| Q update | `normalize()` divides the Q values of each state by their sum, destroying the Bellman meaning; `alpha=1` | The new implementation uses standard Q-Learning, compared against the old implementation |
| Data | `Reward.txt` 22 episodes, `Score.txt` 51 episodes (many degenerate episodes of 5–60 points in the later part), maximum 372 | Reference for the old implementation only, not used as an evaluation set |

## 4. Environment specification (faithful port + explicit deviations)

- 5 actions: 0 stay, 1 right (+1,0), 2 down (0,+1), 3 left (-1,0), 4 up (0,-1). Hitting a wall = stay in place.
- Start: Pacman and the 3 ghosts are placed randomly on walkable cells (a ghost is not on the same cell as Pacman), and the pellet on the spawn cell is cleared.
- Episode flow: Pacman moves → eats → collision check → (if all pellets have been eaten, **win immediately**, the ghosts do not move any more) → ghosts move → collision check. Truncation at 1000 steps.
- Ghosts: candidate directions exclude turning back; with probability `chase_prob` (default 0.3) the direction with the smallest Euclidean distance to Pacman is chosen, otherwise random.
- **Deviation**: turning back is allowed only when a ghost has no way to go (the original code throws an exception in that case; this map has no dead ends, so it is not actually triggered).
- Reward (for training, separate from the evaluation metrics): pellet +1, death −10, win +10, −0.01 per step. The original's shaping of "distance to the nearest pellet gets closer ±0.1" is **not used** (it depends on the nearest pellet, which jumps, and is not a potential function).
- **Differences from the original Java reward (complete list)**: Java's `getReward` is: −100 if the **target cell** of the chosen action falls within the 8-neighbourhood of any ghost; otherwise +1 if the target cell has a pellet; otherwise ±0.1 according to the change of the BFS distance to the nearest pellet; Q is not updated during escape; the update rule also has `alpha=1` and a per-row normalisation of the Q values. Python uses +1 (pellet) / −10 (**actual collision**) / +10 (win) / −0.01 (per step), no distance shaping, and the standard TD update. This is a deliberate redesign, not a port: `legacy` does not replicate Java's training process, it replicates only its **action policy under the default configuration (`readQ`, `Qindex=20`, no training)**, under which the reward and update do not affect behaviour.
- **Differences from the original Java in termination timing (explicit deviation, effect not quantified)**: Java's `remainGold` is updated only when the panel is redrawn (`GamePanel.draw`), so the win decision lags by one frame; in that frame the ghosts move as usual, and after a death the subsequent logic of the same frame is also executed as usual; Python wins in the same step in which the last pellet is eaten, and death terminates immediately. The score definitions on both sides agree (both are the number of pellets eaten), but the effect of these rule and recording differences on the **score distribution, the number of steps and the classification of terminations has not been quantified**, and no conclusion should be drawn until a Java/Python comparison from specified initial states is done; "the mean is unchanged" cannot be inferred from "the score definitions agree" (in Java's `GamePanel` win and lose are two independent `if`s, and if both hold in the same turn each is recorded once). The consistency test between `legacy` and Java (z test on the mean + KS test) can only show that **no difference was detected at the distribution level**, not that the step-by-step transitions are identical; Java uses the unseeded `java.util.Random`, so episodes cannot be compared one by one, and no step-by-step comparison from specified initial states has been done under the JDK either.
- Observation (convolutional networks): `obs="fields"` (default) is `(7, 24, 32)`: walls, pellets, Pacman, ghosts, previous ghost positions (which give the heading), plus two **BFS distance fields** (shortest-path distance from each cell to the nearest pellet / nearest ghost, normalised to [0,1], walls are 1). `obs="grid"` has only the first 5 raw channels and is used only for the control experiment (see deviation 3 in section 9). The MLP uses 29-dimensional engineered features.
- Scenarios: `standard` (default rules) and `hard` (`chase_prob=0.7`, not seen in training, used only to test generalisation).

## 5. Algorithm ladder and depth increase

| Level | Agent | Role |
|---|---|---|
| L0 | `random` | Lower bound |
| L1 | `greedy-bfs` only eats pellets, no dodging | Upper-bound reference without dodging |
| L2 | `legacy` replicates the Java **action policy under the default configuration (`readQ`, `Qindex=20`)**: BFS direction + hand-written escape (including the quirk); and its equivalence to BFS is verified with line 21 of `data/QTable.txt` (the Java training update is not replicated) | **The old version to be surpassed** |
| L3 | `safe-heuristic` strong hand-written: BFS pellet eating but avoiding the ghost threat zone | To judge whether RL is really stronger than "writing the rules carefully" |
| L4 | Standard tabular Q-Learning, 64 states (pellet direction × ghost bearing), **dodging is also learned** | Corrects the old implementation and completes the design in the comments |
| L5 | MLP-DQN (engineered features, ~2×128) | Neural-network starting point |
| L6 | CNN-DQN (2 convolutional layers + fully connected) | Introduces spatial observations |
| L7 | **Fully convolutional ResNet-DQN** (N residual blocks, N∈{2,4,8}) + Double + Dueling + n-step (n=3) | Main line of the depth increase |

Design basis for the depth increase: the map is 32 wide, a single 3×3 convolution extends the receptive field by only 2 cells, and the receptive-field **side length** of res8 (17 convolutional layers) is 35 ≥ the map width 32, but the Q value is read out at the cell where Pacman is, so the receptive-field **radius** is only 17 cells, and it therefore does **not** see the whole map at every position: a geometric check (`tests/test_learning.py::test_res8_readout_does_not_see_the_whole_map_everywhere`) shows that about 80% of the (Pacman cell, other walkable cell) pairs fall within the field of view, and only about 14% of Pacman positions can see all walkable cells (about 37% of the cell pairs for res4). Hence "depth is needed to see the whole map" is only a partially valid hypothesis. Note: after the distance fields are added, the global shortest-path information is already given by the input, and the role of depth becomes "trade-offs/anticipation farther away", and the conclusions of S2/S4 must be read accordingly. The network is fully convolutional and reads out Q at the cell where Pacman is (see deviation 3).

Training algorithm: Double DQN, Dueling, n-step return (n=3, γ=0.99), Huber loss, Adam, gradient clipping, soft update of the target network, multi-environment parallel sampling, linear ε annealing. Implement the above first; **PER, Noisy Net and PPO are listed as optional**, to be done only after the main-line acceptance and if the budget allows.

**Ablation matrix** (≥3 random seeds per cell):
- Depth: MLP / CNN-2 / ResNet-2 / ResNet-4 / ResNet-8 (same number of training steps, distance-field input)
- Input representation (additional evidence, not part of the M6 matrix): raw grid vs distance fields (see deviation 3)
- Algorithm: turn off Double / Dueling / n-step (n=1) one by one on ResNet-4 (see deviation 4)

## 6. Evaluation protocol (preventing leakage and self-serving claims)

- **Seed partition**: validation 5000–5049 (used only to choose checkpoints); **test 10000–10299 (300 episodes), used only once, in the final evaluation**; training-episode seeds are `1_000_000 × (run_seed + 1) + episode index`, disjoint from the previous two (asserted in the tests).
- **Fidelity-check seeds**: the equivalence test of the non-learning baselines against the original Java uses the dedicated seeds 20000–20299 (300 episodes), disjoint from the training, validation and test seeds (asserted in the tests). Previously `test_baselines.py` used the test seeds for this check — `legacy` is a deterministic non-learning policy, so there was essentially no effect, but it literally conflicted with the previous item and has been corrected following the external audit.
- **Dedicated partitions of the preregistered study (architecture × n-step)** (named seed sets in `evaluate.py`, resolved at run time according to `val_set` when training runs): checkpoints are chosen with `prereg_val` 21000–21049; **sealed test `prereg_test` 30000–30299**, the default formal entry point is `scripts/prereg.py final-eval` (needs the integrity manifest and an explicit `--unseal`); this is protocol-based sealing — the low-level Python API, the public seed constants and source modifications do not provide a guarantee that cannot be bypassed — and the test suite never reads its real seeds; smoke evaluation `smoke_eval` 40000–40009; training-episode seeds keep `1_000_000 × (run_seed + 1) + episode index`, with run_seed 100–104 for the formal runs and 900/901 for smoke. `test_seed_partition.py` asserts, from the actual constants and `train_seed`, that the above partitions and the training streams of the old run_seed 0–4 are pairwise disjoint (k ≤ 300008), and asserts that validation intervals such as 20000–20049 that overlap EQUIV are rejected. The uses of the old 5000–5049 / 10000–10299 / 20000–20299 are unchanged.
- All agents are evaluated on the same test seeds (same starting points) ⇒ **paired** comparisons are possible.
- Metrics (independent of the training reward): **mean score** (pellets eaten, 0–377), **win rate**, **death rate**, mean survival steps. Primary metric: mean score; secondary metric: death rate.
- Statistics: each metric gets a 95% bootstrap CI; comparisons between agents use the CI of the paired bootstrap difference. RL results report the mean ± standard deviation over 3 training seeds, and list the per-seed values.
- The raw per-episode records are written to `results/*.json`, and the report may only be generated by scripts from these files.

### Final acceptance thresholds

**Must pass (MUST)**
- M1 `pytest` all green, including: the Python map **cell-for-cell identical** to the source of `Game.java`, 378 pellets in total / 377 edible, ghosts never enter walls and never turn back, collision/win/truncation logic, same seed fully deterministic.
- M2 `acceptance.sh --quick` finishes within 10 minutes in a clean environment; evaluating the same checkpoint twice gives bit-for-bit identical metrics (**on the same device**; the per-episode results of evaluation differ between GPU and CPU, see `docs/RESULTS_COMPARISON.md`).
- M3 The baseline table (L0–L3) and tabular Q (L4) are completed, with CIs.
- M4 **The final deep agent is better than `legacy` on the test set**: the lower bound of the 95% CI of the paired difference of mean score > 0, and the death rate is lower (direction with the paired CI lower bound > 0).
- M5 The final deep agent is better than the L4 tabular Q (mean score, paired CI lower bound > 0).
- M6 Every cell of the ablation matrix has ≥3 seeds, and all reported numbers are generated by `make_report.py` from `results/*.json`.
- M7 Zero changes to the original Java code (`git diff <base> -- '*.java' Images data/QTable.txt` is empty); the README explains how to run the old and the new versions.

**Expected to be achieved (SHOULD; if not achieved, the gap and the reason must be stated truthfully in the report; this does not count as an acceptance failure)**
- S1 The deep agent is not worse than `safe-heuristic` by more than −3% (mean score).
- S2 The best ResNet depth is significantly better than the small CNN (paired CI lower bound > 0); if this does not hold, report the conclusion "depth brings no benefit on this task" and the evidence.
- S3 In the `hard` scenario, the advantage of the deep agent over `legacy` is maintained.
- S4 Receptive-field hypothesis test: whether the score trend for N=2/4/8 agrees with the prediction "the receptive field grows with depth" (note that res8 does not cover the whole map everywhere, see section 5).

1. Open `results/replays/*.gif`: three clips, before training (random), legacy, and the final agent; confirm by eye that the behaviour is reasonable (dodges ghosts, does not jitter in place).

3. Confirm that the test seeds appear only in the final evaluation (check the seed source and the logs of `train.py`).
4. Read the section "unmet items and limitations" of `RESULTS.md` and confirm that no failure was hidden.

**Deviation record** (appended during implementation, format: date / what was changed / why):

- 2026-10-08 / Section 6 seed partition: the original wrote "training stream 0–99999", which overlapped validation 5000–5049 and test 10000–10299 and carried a leakage risk; changed to training seeds ≥ 1,000,000 segmented by run_seed. Reason: the plan was self-contradictory, found before any result was produced.
- 2026-10-08 / Sections 4 and 5 network structure and observation (deviation 3, in two steps, both based on trial training on the validation set, the test set was not used):
  1. The initial convolutional network was "flatten the feature maps → fully connected → Q". With the same hyperparameters it hardly learned: CNN-2 scored ≈12 after 4.4 wan steps of training (random ≈8), ResNet-2/4 had validation scores of 3.9/3.7 at 2 wan steps (random 8.3), while the MLP (engineered features) had 82 at 4 wan steps and 258 at 12 wan steps. Raw logs: `results/reference/pilot_rawgrid/`.
  2. I first guessed that it was an input problem and added two BFS distance-field channels, which was **ineffective** (CNN-2 validation 4.9 at 4.5 wan steps). The real cause is the structure: flatten + fully connected has to learn by itself the multiplicative relation "Pacman position × neighbour-cell values". After changing to **fully convolutional, reading out the Q value at the cell where Pacman is** (weights shared across positions, receptive field = the range seen by depth) it worked immediately (CNN-2 validation 36 at 1.5 wan steps; with the same structure, the raw-grid ResNet-4 had 58 at 4.5 wan steps ≈ 51 with distance fields).
  3. Therefore: the convolutional networks use 7-channel input (including the distance fields) by default, and **raw-grid ResNet-4 × 3 seeds** is listed as a formal control experiment, answering "do the distance fields actually help" with data rather than asserting it from one trial training.
  4. The learning rate was changed from 2.5e-4 to 5e-4 (CNN-2 trial training at 6 wan steps, validation 57.6 → 91.7), used uniformly for all architectures.
- 2026-10-08 / Section 5 base of the algorithm ablation (deviation 4): the original wrote "ablate on the best-depth ResNet"; in order to control compute (one ResNet-8 run takes about 105 CPU minutes) and avoid results depending on a selection, it is **fixed in advance to ResNet-4**.
